国产浏览器（尤其是 360、奇安信）在前端确实有一些需要特别注意的点，虽然它们大多基于 Chromium，但和原生 Chrome/Edge 仍有差异，尤其在政企、信创环境中更明显。

## 1 带双核的浏览器（代表：360、QQ 浏览器等）

有极速模式（Blink/Chromium）和兼容模式（Trident/IE），部分用户切换为兼容模式后默认为兼容模式，现代化 web 项目基本不再兼容 IE，例如 Vue，因此需要添加特殊标签让浏览器强制切换为极速模式，即 Chromium 内核。

```html
<meta name="renderer" content="webkit">
```

+ 用户手动切换过模式后，浏览器会记住该域名的偏好，meta 可能失效，此时只能写兼容页面判断环境然后引导用户切换内核；
+ 老版本 360 内核较旧，ES6+、部分 CSS（Grid、部分 Flex 细节、新伪类）可能需要 polyfill 或降级，这里走传统 Webpack、vite 的 Babel 降级插件把产物生成两份，按需加载即可。

## 2 基于 Chromium 自研的一些国产浏览器（代表：奇安信浏览器）

+ 通常内核版本无法与最新的 Chromium 对齐，需注意新式 API 的兼容性，browserslist 里可加上对较旧 Chromium 的支持，或单独打兼容包；
+ UA 通常带 Qaxbrowser，可用来识别；
+ Flex 基线对齐、媒体查询生效时机、部分新属性可能有细微差异，优先使用成熟的属性；

## 3 其他共性小问题

### 3.1 中文字体渲染异常

**问题表现：**字体显示不清晰、出现方框或乱码，尤其在信创系统上更严重。

**问题原因：**

1. 信创操作系统（麒麟、统信）默认中文字体与 Windows 完全不同。
2. 360/奇安信在硬件加速、DirectWrite 字体渲染开关上行为不一致。
3. Canvas 绘制时字体未加载完成就执行，导致回退到不支持中文的默认字体。

解决方案：

```css
/* 确保完整的字体回退链，开启抗锯齿，解决模糊和锯齿问题 */
body {
  font-family: "PingFang SC", "Microsoft YaHei", "Hiragino Sans GB",
               "Noto Sans CJK SC", system-ui, sans-serif;
  -webkit-font-smoothing: antialiased;
}
```

```js
// Canvas 绘制前必须等待
await document.fonts.ready;
```

### 3.2 企业安全策略强管控

**问题表现：**复制不了，没有任何提示报错

**问题原因：**奇安信、360 企业版专门针对政企客户增加了「内生安全」策略，可强制禁用剪贴板、下载、右键菜单、开发者工具、截屏等行为。这些限制在浏览器进程层面直接拦截，前端 API 调用会静默失败。

**解决方案：**

对敏感操作做 try-catch + 降级 + 明确提示。

```js
async function safeCopy(text) {
  try {
    await navigator.clipboard.writeText(text);
  } catch {
    // 降级到 execCommand 或提示用户手动复制
    ElMessage.warning('当前浏览器安全策略限制了复制，请手动选择文字复制');
  }
}
```

### 3.3 打印时字体丢失、样式错乱

**问题表现：**打印时字体丢失、样式错乱

**问题原因：**打印引擎与屏幕渲染引擎是分离的。国产浏览器在打印时经常忽略 Web 字体或复杂字体栈，强制回退到系统默认打印字体，导致字体、行高、分页发生变化。

**解决方案：**

系统字体全局优先使用系统已安装的打印友好字体（宋体最稳定），其次设置打印时的样式。

```css
@media print {
  body {
    font-family: "SimSun", "宋体", serif !important;
    -webkit-print-color-adjust: exact;
    print-color-adjust: exact;
  }
}
```

### 3.4 CORS / 跨域请求被更严格拦截

**问题表现：**跨域请求发起失败。

**问题原因：**360 和奇安信叠加了自身的「增强防护」「网页防篡改」等安全模块，对 CORS 预检请求（OPTIONS）和响应头的校验比标准 Chromium 更严格，有时会额外拦截正常请求。

**解决方案：**尽量不要跨域，成熟的系统基本也是同域请求，若一定要跨域请求，可架设代理服务器进行统一转发，或者确保生产环境完整的 CORS 头按最严格最标准的实现。

### 3.5 文件上传 / 下载被拦截

**问题表现：**文件上传 / 下载失败

**问题原因：**安全策略可直接阻止 a[download] 触发的下载行为，或对大文件上传进行中断/拦截，属于浏览器进程级的防护。

**解决方案：**下载提供「复制链接」兜底；上传采用分片 + 失败重试，或者新标签打开试试。

### 3.6 Canvas / WebGL 性能明显下降

**问题表现：**ECharts 等 canvas 渲染或 D3.js 等渲染图形卡顿甚至死机。

**问题原因：**部分设备上国产浏览器默认关闭硬件加速，或运行在国产 GPU 上，导致 Canvas/WebGL 走软件渲染，性能大幅下降。

**解决方案：**检测低性能环境后主动降级（降低帧率、关闭复杂效果、优先使用成熟图表库），例如使用 SVG 模式渲染，减少数据量。
