## 1 什么是内存泄漏

程序的运行需要内存，只要程序提出要求，操作系统就必须供给内存。

对于持续运行的进程，必须及时释放不再使用到的内存，否则内存占用越来越高，影响系统的性能，甚至导致进程崩溃。

也就是说，不再用的内存，如果没有及时释放，就叫做内存泄漏。

## 2 JavaScript 中的垃圾回收

浏览器的 JavaScript 具有自动的垃圾回收机制（GC），执行环境会负责管理代码执行过程当中使用到的内存。垃圾收集器会定期找出那些不再继续使用的变量，然后释放其内存。

这个过程不是实时的，GC 回收开销比较大并且 GC 进行时会暂停响应其他操作，所以垃圾回收器会按照固定时间周期性执行。

### 不再使用的变量如何定义？

可能是生命周期结束的变量、可能是局部变量。全局变量的生命只有在浏览器卸载页面时才会结束。局部变量只在函数执行的过程中存在；闭包的话由于内部函数的原因，外部函数不能算作结束，因此闭包的局部变量生命周期也不能算作结束。

### 垃圾收集器是怎么实现跟踪到底哪个变量没有使用？

JavaScript 通常有以下两种实现的方式：标记清除和引用计数。

## 3 标记清除

JavaScript 最常用的垃圾回收方式是标记清除。

垃圾回收器从一组根（Roots）出发，顺着引用关系往下找，能找到的对象就叫可达，找不到的就叫不可达（可以释放）。

### 常见的根有哪些？

- 全局对象（`window` / `globalThis`）
- 当前正在执行的函数里的局部变量、参数
- 调用栈上的所有变量
- 闭包中被引用的变量

垃圾回收器从根对象出发，沿着引用关系遍历，所有能访问到的对象都是可达的，访问不到的就是垃圾，可以被清除。

### 内存会被回收的代码示例

```javascript
function test() {
  let objA = { name: 'A' };
  let objB = { name: 'B' };

  // 互相引用
  objA.ref = objB;
  objB.ref = objA;
}

test();
```

思路：

- 函数执行时，`objA` 和 `objB` 都是可达的（从当前执行上下文能找到）。
- 函数执行完毕后，局部变量 `objA` 和 `objB` 都离开了作用域。
- 此时从根（全局对象、调用栈）出发，已经找不到 `objA` 和 `objB` 了。
- 虽然它们互相引用，但因为从根访问不到，所以被判定为不可达，会被标记清除算法回收。

### 内存不会被回收的代码示例

```javascript
let globalRef;

function test() {
  let objA = { name: 'A' };
  globalRef = objA; // 把对象挂到全局
}

test();
// 此时 objA 仍然可达（通过 globalRef），不会被回收
```

思路：

- 函数执行时，`objA` 是局部变量，属于当前执行上下文，此时它是可达的。
- 执行 `globalRef = objA` 后，这个对象被全局变量引用了。
- 函数执行完毕，局部变量 `objA` 离开作用域，但是对象本身已经通过 `globalRef` 被全局对象引用。
- 垃圾回收器从根（全局对象）出发，仍然能通过 `globalRef` 找到这个对象，所以它是可达的，不会被回收。

## 4 引用计数

引用计数的方式是跟踪记录每个值被引用的次数。

当声明一个变量并将一个引用类型赋值给该变量时，则这个值的引用次数是 1；如果相同的引用值又被赋值到新的变量，则该值引用次数 +1。如果该变量的引用值被改变（清空或者赋值了其他值），则这个引用值的引用次数 -1。

当这个值的引用次数变成 0 时，则说明没有任何代码能够使用该值了，就可以将其占用的内存空间回收回来。

垃圾回收器在下个周期运行时，就会释放掉那些引用次数为 0 的值所占用的内存空间。

使用引用计数策略的浏览器，会遇到一个很严重的问题：循环引用。

循环引用是指对象 A 的属性中指向了对象 B 的引用，对象 B 的属性中也有指向对应 A 的引用。

### 正常的引用计数过程

```javascript
let objA = { name: 'A' }; // 引用次数 = 1

let objB = objA; // 引用次数 = 2（又被 objB 引用）

objA = null; // 引用次数 = 1（objA 不再引用）

objB = null; // 引用次数 = 0 → 可以被回收
```

思路：

- 每多一个变量指向这个对象，引用次数就 +1。
- 当变量不再指向它（赋值为 `null` 或指向别的值）时，引用次数 -1。
- 当引用次数变成 0 时，说明已经没有人用这个对象了，内存可以被回收。

### 循环引用问题

```javascript
function test() {
  let objA = {};
  let objB = {};

  objA.ref = objB; // objB 引用次数 +1
  objB.ref = objA; // objA 引用次数 +1
}

test();
```

思路：

- 函数执行完后，局部变量 `objA` 和 `objB` 都离开了作用域。
- 但因为它们互相引用，各自的引用次数都还是 1，永远到不了 0。
- 所以引用计数算法无法回收这两个对象，造成内存泄漏。

## 5 其他知识点

因为引用计数无法处理循环引用，会导致内存泄漏。标记清除通过「从根出发判断可达性」，即使对象互相引用，只要从根访问不到就会被回收，因此更可靠。现代引擎还在此基础上做了分代、增量等优化，性能也足够好。

### 分代回收（Generational）

大多数对象生命周期很短。引擎把内存分成新生代和老生代：

- **新生代**：存放新创建的对象，回收很频繁（Minor GC）
- **老生代**：存放活得比较久的对象，回收较少（Major GC）

这样能大幅提高回收效率。

### 增量回收（Incremental）

传统标记清除会「一卡到底」（Stop-The-World），整个 root 遍历一遍。增量回收把标记和清除工作拆成很多小步骤，穿插在 JS 代码执行中间进行，减少页面卡顿。
